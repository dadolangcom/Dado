# app:ui

app:ui — a UI framework whose layout and text are bound to a monospace cell
grid, and whose region interiors are not.

**The unit is the cell.** Every rectangle, every minimum size and every
position this package speaks is a whole number of cells (`cell.CellRect`,
`cell.CellPoint`). A widget that later owns a free-pixel interior — an
image, a viewport — gets a rectangle in cells like every other node and does
what it likes inside it; no pixel ever reaches the layout.

── The tree ───────────────────────────────────────────────────────────────

A `Control` is a handle, `(slot, generation)`, into one package-owned pool
of nodes. Each node records its kind, an opaque `rawptr` state, its parent,
its first and last child and its two siblings, the rectangle layout gave it,
the minimum size it last measured, four flags (expand horizontally, expand
vertically, visible, focusable) and its dirty bits. Removing a node bumps its
slot's generation and threads the slot onto a free list, so a handle held
past the removal no longer matches, and the node that later reuses the slot
is not reachable through it.

There is one implicit root, created on first use and answered by `root()`:
a vertical box that `update` sizes to the screen rectangle. `create` with a
`NIL` parent attaches the new node to the root.

── Kinds and hooks ────────────────────────────────────────────────────────

There are no methods, subclasses or virtual tables. A widget is a
constructor plus a state record, and its behaviour is a `Kind`: a set of
function references (`Hooks`) registered once with `register_kind`. Every
hook receives the node's handle and its state pointer; any of them may be
nil, and each type below says what a nil one means. The node's state is
either a pointer the widget owns and gives back in its `free` hook, or a
zeroed block from `create_owned` that this package frees after the `free`
hook has run.

── Signals ────────────────────────────────────────────────────────────────

A signal is an interned name (`signal`) and a connection is a function
reference plus a context pointer on one node (`connect`). `emit` runs a
node's connections for one signal in the order they were made. A removed
node takes its connections with it.

── Two dirty bits, two walks ──────────────────────────────────────────────

`mark_layout(c)` sets layout-dirty on `c` and on each ancestor until it
meets one that is already layout-dirty, and sets paint-dirty on `c`.
`mark_paint(c)` sets paint-dirty on `c` and a "some descendant needs paint"
bit on each ancestor until it meets one that already has it. Both bits
therefore reach the root whenever anything visible is dirty, and `update`
answers an idle frame by reading the root's bits alone.

`update(screen)` runs the layout walk and then the paint walk:

  - measure, bottom-up, only through layout-dirty nodes: a clean subtree
    keeps its cached minimum and is not entered;
  - arrange, top-down from the root: a node is arranged when it is
    layout-dirty or its rectangle changed, and a node whose rectangle
    changes becomes paint-dirty;
  - paint, in tree order (a parent before its children), entering only
    subtrees that are paint-dirty or hold a paint-dirty descendant. A node
    that repaints forces its whole subtree to repaint, because its paint
    may overwrite its children's cells. Each paint hook receives the node's
    rectangle clipped to every ancestor's, and every node repainted, hook
    or no hook, records itself as the owner of those cells in the hit map
    that routes the mouse (`hit`, in input.dado).

A changed screen rectangle makes every node layout- and paint-dirty.
Invisible nodes are laid out as empty rectangles, and neither they nor their
subtrees are measured, arranged or painted. Every bit the walks reach is
clear when `update` returns.

Cells a node stops covering are repainted by its parent: removing or hiding
a node marks its parent for paint, and a container whose children cover
less than they did marks itself from its arrange hook (`mark_paint` works
there).

While `update` runs, the tree's shape is frozen: `create`, `remove`,
`mark_layout` and every setter that marks layout do nothing, `mark_paint`
does nothing during the paint walk, and `set_rect` does something only for
a visible child of the node whose arrange hook is running.

── Layer groups ───────────────────────────────────────────────────────────

Every node paints into one of the grid's layer groups (`grid.target`): the
one `set_layer` gave it, or else its parent's, down to the root's
`grid.BASE`. A layer is a whole screen of cells over the ones below, so a
floating subtree drawn into its own layer covers the base without the base
repainting under it, and uncovers it by clearing its own cells rather than
by repainting the base. layers.dado has the rules.

── Focus ──────────────────────────────────────────────────────────────────

One node at most has focus, and keys go to it (`dispatch`). A program moves
focus between panes with `focus_next`/`focus_prev`, which step through the
focusable nodes in view in tree order, and asks whether focus is inside a
subtree with `focus_within`. A focus move marks nothing for layout or paint:
a box whose look follows it is chrome, which is rebuilt, and a widget whose
cells follow it asks to be repainted (`set_focus_repaint`).

── Chrome ─────────────────────────────────────────────────────────────────

A kind with a `style` hook answers the `StyleBox` it is drawn with now;
`chrome_sync` turns every visible node's box into the grid's pixel chrome
when something it depends on changed, and does nothing on an idle frame.
chrome.dado has the rules, and why a shadow's bleed marks nothing.

── Totality ───────────────────────────────────────────────────────────────

Every public entry point accepts any handle. A handle that is `NIL`, names a
slot outside the pool, names a removed node, or names a slot that has since
been recycled for another node reads as the empty thing — an empty
rectangle, `NIL` parent and children, zero counts, a nil state, false — and
every mutation through it does nothing. No entry point aborts on one.

── Storage ────────────────────────────────────────────────────────────────

There is no fixed cap on nodes, children, kinds, signals or connections:
every pool grows by doubling. The allocator is the ambient one — `#default`
— at the first call that creates anything, and every later growth passes it
explicitly, because a later call may run inside a per-frame scratch arena
that is rolled back every frame.
