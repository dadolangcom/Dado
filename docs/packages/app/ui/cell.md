# app:ui/cell

app:ui/cell — the vocabulary of a cell-grid UI: the cell, the rectangle in
cells, the column, and the seam where right-to-left text will one day go.

Everything that speaks in cells imports this one package: the renderer
(`app:ui/grid`), the tree and the layout (`app:ui`), and the editor. It is
one package because a record re-exported across a package boundary loses its
slot names (ERR0410), so a type defined once here and imported everywhere is
the only shape in which every package reads `r.cols` rather than `r[2]`. It
holds no state: every function here is arithmetic over its arguments, which
is what lets the tests exercise it with no window and no face.

**The unit is the cell, and it is an integer.** Layout, text measurement and
hit testing all happen in whole cells; only a region's interior — an image,
a viewport — has pixels, and those never leak into a cell count. A pixel is
a cell times the cell size, which the renderer derives from the live face.
