# core:cbor

core:cbor — CBOR (RFC 8949): an append writer, a pull reader, and
diagnostic notation.

**Tier N W H. Script class S.** Pure Dado over `core:chars`, `core:fmt`
and `core:slices`: no `foreign` block and no state, so it builds and runs
freestanding, on the web and hosted, and any thread may use it.

**What raises into a script.** Everything: every function and every
method of `Writer` and `Reader`, each promised by the `#assert_raises` on
the line above it.

    cbor.Writer w = cbor.writer()
    w.map(2)
    w.text("name")
    w.text("oak")
    w.text("size")
    w.array(2)
    w.uint(600)
    w.float(18.5)
    try ref []u8 bytes = w.finish() else code:
        ...
    defer #delete(bytes)

    cbor.Reader r = cbor.reader(bytes[:])
    try cbor.Container m = r.map()
    for r.more(&m):
        try string8 key = r.text()
        try r.skip()

The writer writes definite lengths only, every head in its shortest form,
and each `float` in the narrowest width that holds it exactly (RFC 8949's
preferred serialization). Map keys go out in the order they are written;
`sort_map` puts a finished map in the deterministic order. The bytes grow
on the allocator that was `#default` when `writer` was called.

The reader allocates nothing except in `bytes_copy`, `text_copy` and
`diagnose`. The strings it answers are views into the input. It reads
indefinite lengths too, and malformed input fails with a code and leaves
the reader where it was.

The common tags have verbs of their own: `date_time` (tag 0, RFC 3339
text), `epoch` and `epoch_float` (tag 1, seconds since 1970), and
`bignum` and `negative_bignum` (tags 2 and 3, big-endian bytes), on the
writer and the reader both. Any other tag is `tag(number)` and then its
content.

**Error codes: `Error`, 1200 to 1299**, a range no other package's codes
share; `message(why)` answers a sentence for each.
