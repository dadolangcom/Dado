# core:script

core:script — the native runtime a DadoScript program runs on: QuickJS-ng, the
fork, embedded. A program does not call it by name: it writes the verbs, and
the compiler lowers them onto this package.

    import "core:script"

    // `Counter.dados` beside this file is a script class.
    !i32 main():
        try VM vm = #script_vm(on_error: script.QUIT)   // an engine on `#heap`
        defer #delete(vm)
        try Counter c = #script_new(vm, Counter, 40) else code:
            return code                               // its text is on stderr
        defer #delete(c)
        c.add(2)                                      // untried: a failure ends the program
        try i64 n = c.total() else code:
            if code == script.STOPPED:
                return 0
            return code
        return 0

**What a program names here** is small, and it is the package's promise:
the reserved codes a verb fails with (`STOPPED`, `STALE`, … below), the
`on_error:` policies `QUIT` and `CONTINUE`, `counters` and `Counters`,
`live_handles`, `UNTRIED` and the limits `MAX_ARGS`, `MAX_NEST` and
`MAX_CHANNELS`. **Everything else public is runtime glue**: public only
because the C the compiler emits calls it, each such declaration's doc
comment starting `Runtime glue:` under a section heading that says so. The
glue is versioned with `dadoc`, not with the standard library: it may change
in any release that also changes the compiler, and a program never calls it.

**Limitations.** A call into a script takes at most `MAX_ARGS` (16)
arguments and a program's scripts bind at most `MAX_CHANNELS` (64) channels,
each refused where it is written (`ERR1221`, `ERR1222`). At run time, runs
nest at most `MAX_NEST` (64) deep; the process holds at most 65,535 live
handles; at most 127 VMs receive on channels at once; a failure's text is
kept to 4 KiB; and a reload's or a mod's path to 1,024 bytes — each past its
limit failing `NO_MEMORY` or saying so on the error sink. **On the web**, a
reload, a module loaded by path and a pause on the page's main thread are
refused where they are written: the page's engine cannot compile new code at
run time, and its main thread cannot wait.

**Tier W H.** Every hosted target (Linux, macOS and Windows) on the
engine's archive, and the web on the page's own engine; never `#NONE`,
which is refused by design (below).

**What this package is.** The seam the generated glue of `#script_vm`,
`#script_new`, `#script_run` and member calls through a handle calls: an
engine on the host allocator, a registry of embedded ES modules that the engine's module loader reads by name, `print` and
`println` on the engine's output sink, and an uncaught exception's text on
its error sink; and the interrupt hook, with stopping and pausing a running
script (`stop.dado`); the sink stack each run pushes and pops
(`sinks.dado`); and the reserved codes a verb answers and the failure's text
`#script_error()` reads (`failure.dado`). It is not all of the runtime
library: the print suite's rendering rules arrive with the row that owns
them.

**The engine is a toolchain component, never compiled in a program's
build.** `quickjs.h` is not in this directory: it is the header of the
archive `./dado` links, built once per target triple, compiler and flags from
the pinned upstream and the fork's patch series (`tools/quickjs/build.sh`).
The build learns that it needs the archive from the compiler: a program whose
live set holds this package gets an `engine quickjs` line in its build
manifest, and the driver answers it with the archive's directory on the
include path and the archive on the link line. A program that never reaches
this package links nothing and stays one translation unit.

**Hand-restated, not generated, and checked all the same.** Every other
binding of a C library in this tree is `bindgen`'s output over a header in
the tree. This header is the output of the patch series applied to a pinned
upstream, and it lives beside the archive in the cache: a copy committed
here would be a second source of truth for a header that has one. So the
declarations below are the handful this package calls, restated by hand,
and the emitter's assertions check each against the real header on every
build — every signature's C type by `_Generic`, every restated struct's
layout by `sizeof`/`offsetof`, and every constant's value comes from C.

**No scripting on `#NONE`; on the web, the page's engine.** QuickJS-ng
needs a hosted C library even with its allocator routed through Dado's, so a
freestanding build that reaches this package is refused: the `foreign` block
names a header outside C's freestanding set (`ERR1032`), and the driver
refuses an `engine` line on such a target by the same reason. On the web a
script runs on the page's own engine and a web build links none:
`quickjs.h` is a header the compiler's web runtime supplies, implementing
every function below over the JavaScript engine beside the module, so this
package compiles unchanged there; its scripts are files beside the module,
never source an engine compiles. **On Windows** the archive is built as for
any other triple (`x86_64-windows-gnu`, by the pinned zig), and the package
has no arm of its own: what it needs of the operating system — a lock and a
condition per engine — is `core:threads`', the files a reload or a mod
reads are `core:io`'s, and the separator a reload's path is joined with is
`core:path`'s.

**What raises into a script.** Little, by what the package is: the seam
between a script and its host, so nearly every function here holds the
engine's values as addresses (`^JSContext`, `JSValue`'s pointer payload)
or a handle as a `rawptr`, takes a name as a `cstring`, or calls the
engine's header. That is every verb and its `_or_quit` twin, the private
engine calls they are built on, the thunk helpers (`take_`, `give_`,
`read_`, `answer_`), the stop and pause entries (which also take
`core:threads`' locks and an atomic word), the handle table (a lock, so
`live_handles` too), the channels (atomic flag words), `counters` (the
engine's state, through the handle table's lock), the sinks (a `Sink` holds
a `rawptr`) and the reload and mod loaders' engine halves. None of them is
promised, and none can be without leaving the engine. Promised, each by the `#assert_raises`
above it: the lend fingerprint's arithmetic (`mix`, `mix_float`,
`mix_string`), `exit_status`, `failure_text` and `pend_policy`, and the
private text and number helpers beneath them — the failure text's buffer,
the reload's manifest and header readers and its path, the mod loader's
file names, and the handle table's bit packing.

**Values cross as scalars, and `int` in its tiers.** A DadoScript `int` is
exactly `i64`, held in the smallest canonical tier that fits: a 32-bit
integer, a double exact to 2⁵³ − 1, or a BigInt beyond. An argument is
built in that tier and an answer read from any of the three, so a value
past 2⁵³ crosses both ways exactly. `f64`, `bool` and strings cross as themselves.
